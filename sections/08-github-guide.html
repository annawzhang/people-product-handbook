4. 我自己怎么用（维护 checklist）

  • 置顶 6 个（网页 Pin）：handbook 或 hiring-agent、retail-kpi-cockpit、explainable-talent-scoring、voc-voice-agent、hiring-copilot、hris-prototype。
  • Profile 表格：每发新仓加一行「来源 · 链接 · 一句话 · 技术」。
  • 手册同步：新板块补 architecture 页；Agent 类一定写工具白名单。
  • 公开前自检：搜手机号、真实门店名、内网 URL、同事姓名；Pages 打开 tests。
  • 面试前：本地 python3 run.py / 打开 tests.html，确认绿。
  • 诚实表述：README 写明「虚构数据 / 规则引擎非托管 LLM」。

5. 面试怎么「带逛」GitHub（话术）

我 GitHub 上是一套公开复刻，不是公司代码。
建议从 People Product Handbook 看架构，再点两个 Demo：
1）Hiring Agent —— 展示 Agent 只能调规则引擎；
2）人才评分或 VOC Agent —— 展示可解释与「无证据不说话」。
如果您关心统计，再打开 People Stats Kit 看 z 检验和样本量。

6. Demo 深潜路径（15 分钟版）

  1. Handbook 总览 → 点开「招聘」页看序列图。
  2. Hiring Agent：问「超时候选人」→「初筛 Cxxx」→ 故意「推进」触发规则拒绝。
  3. Hiring Copilot：同一人在看板上对照证据高亮。
  4. Stats Kit：讲开实验前样本量。
  5. VOC Agent：价格关口必须出原声卡片；再测禁止话术。

7. Best practices（账号层面）

  • 一个对外账号 annawzhang；学校邮箱可放 Profile，手机号不放公开页。
  • 仓库名用英文短横线，description 写中文能力句 +「虚构数据」。
  • 每个可运行仓：README 截图/报告、Pages、测试入口三件套。
  • 不要把实习内部仓设为 Public；要展示就复刻。
  • 比赛贡献用 PR 链接（如 OpenSeek），写清自己负责部分。
