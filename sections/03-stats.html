3. Follow-up

追问答法
p<0.05 就一定要全量推广？还要看 lift、功效、是否多重比较、业务成本。
为什么漏斗要用 Wilson 而不是正态近似？小样本/极端比例时 Wilson 更稳。
删失是什么？观察结束时尚未入职（仍在 Offer 等），不能当成失败。
和你统计学背景怎么挂钩？本硕方法直接产品化：能算、能解释、能进 SOP。

4. 技术栈梳理

项选择
依赖仅 Python 标准库（math / random / unittest）
正态分位数Acklam 有理逼近（norm_ppf）
交付HTML 报告 + unittest
刻意不用scipy / statsmodels（降低复现门槛）

5. Best practices

  • 先算 n 再开跑；样本不够时报告写「效力不足」而不是「没差异」。
  • 漏斗同时看点估计与 CI，避免「掉了 2 个人」过度解读。
  • 校准 gap 持续为负/正，说明分数系统性偏高/偏低。
  • 与业务约定：显著 + 最小可感知提升（如回复率 +5pp）才推全。

6. Demo 路径

  1. 打开报告 KPI：AB 结论、lift、每组样本量、中位周期。
  2. 漏斗表指一格 CI，解释为何不能只看转化率数字。
  3. 校准表：≥60 分档通过率应高于 0–39。
  4. python3 -m unittest discover -s tests -v（9 passed）。
