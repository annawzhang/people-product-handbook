06 HRIS 流程入转调离 · 编制 · OA
总览 招聘 人才评估 人力量化 用户原声 触达护栏 HRIS Skills

可交互 HRIS 原型

审批链按组织与编制实时算；通过后改人员数据；再按字段映射推 OA（含重试与幂等）。

Demo · ?demo 引擎测试 GitHub

1. 架构图

flowchart LR UI[审批中心 / 组织 / 看板 / OA] --> WF[workflow.js] WF --> DATA[虚构组织与编制] WF --> CHAIN[buildChain 动态审批链] CHAIN --> STATE[申请状态机] STATE --> EFFECT[入职/转正/调岗/离职生效] EFFECT --> OA[字段映射 + 校验 + 重试] OA --> PAYLOAD[OA 报文预览]
flowchart TB subgraph onboard [入职] A1[HRBP] --> A2[用人部门] A2 --> A3{满编或高职级?} A3 -->|是| A4[超编/高职级审批] end subgraph transfer [调岗] B1[调出] --> B2[调入] --> B3{跨事业部?} B3 -->|是| B4[两边负责人] --> B5[HRBP] B3 -->|否| B5 end

2. API / 引擎调用

能力说明
buildChain(type, payload)按流程类型与编制生成审批链快照
批准 / 退回 / 驳回 / 撤回身份校验：非当前节点不可操作
生效逻辑入职加人、转正改状态、调岗改部门、离职回收
OA sync映射、必填校验、502 退避重试、单号幂等

产品化 HTTP 建议

POST /v1/workflows            { type, payload } → chain snapshot
POST /v1/workflows/{id}/act   { action, comment, actor }
GET  /v1/org/headcount
POST /v1/oa/sync              { workflow_id } → { status, retries }

3. Follow-up

追问答法
满编还能入职吗？能，但自动加超编审批节点。
审批中组织变了怎么办？链在提交时快照，进行中不受影响。
OA 失败？退避重试，仍失败进补偿队列；成功单号幂等跳过。

4. 技术栈梳理

原生 JS localStorage · 无后端 · tests.html

5. Best practices

  • 同一人多节点合并，避免重复点两次。
  • 驳回必须写原因；看板监控超时单。
  • OA 字段映射表与代码一并评审。

6. Demo 路径

  1. 打开 ?demo 自动走一单并同步 OA。
  2. 切换身份看待办变化。
  3. 满编部门发入职，指出超编节点。
